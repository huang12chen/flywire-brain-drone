# "Fruit Fly · Micro World" v1 Design Document (Final Trimmed Version)

> ⚠️ This is a historical design document from 2026-09-22, **not an implementation guide**: it contains unrealized feature concepts (such as pause/slow-motion, entity count limits, etc.). Actual implementation is as per `web\manual.html` and `web\world.html`.

Date: 2026-09-22　Status: Aligned with user
Positioning: **Scientific results are primary; the 3D open world is a verification platform + demo showcase**. Target application domain: drone biomimetic obstacle avoidance / anti-interference (biomimetic control).

## 0. Core Scientific Claims (what the experiments aim to prove/disprove)

1. An SNN (1871 nodes / 45524 edges, only adjusting weights, not connections) constrained by **real FlyWire connectome topology** can achieve "visual-wind fusion threat escape control."
2. **Fusion > single modality**: fusion significantly outperforms pure vision in directional accuracy and obstacle avoidance success rate; pure wind sense is a weak cue (short-range / supplementary).
3. **Cross-platform validity**: the same controller works effectively on both a "fruit fly body" and a "drone body" (different mass/thrust/inertia) for hazard avoidance.
4. **Environmental robustness matrix**: performance degradation is quantifiable across four scenarios — clear weather / strong wind (continuous wind-sense stimulation) / pitch black (visual attenuation) / high-speed sneak attack.

## 2. Trimmed Scope (explicitly excluded, listed as future work)

- Pet raising / multi-user product (P3): unrelated to scientific goals.
- Dopamine online learning: destroys reproducibility; if done in the future, must be offline with a locked seed.
- Memory / habituation layer: introduces new variables that contaminate the core controlled experiments.
- Retained as future work items in the report.

## 3. 3D Testbed (P0) Design

- Visuals: Genshin Impact-style cartoon rendering. Gradient sky dome + clouds, distant mountains, fog, sunlight; InstancedMesh grass blades (~6000) swaying, wildflowers, mushrooms, low-poly trees, pond water surface.
- Scenes = experimental variables: 🌿 Grassland (default) / 🌪️ Strong wind (grass bends, aircraft disturbed, continuous wind-sense firing) / 🌑 Pitch black (visual input attenuated by brightness, fireflies) / 🪷 Pond — low-altitude near water.
- Platforms (cross-platform experiment): fruit fly body (1.5 m/s takeoff, lightweight) / quadcopter body (thrust-inertia model, acceleration-limited) — same SNN output.
- Threats (uniformly abstracted as "high-speed approaching objects", generating real looming + wind pressure cues): red diving ball (baseline), tongue-flicking frog, diving dragonfly.
- God-mode console: place/delete entities (≤8), spawn threats, switch scene weather, pause/slow-motion, change body, **one-click run 100 trials for statistics** (metrics identical to train_snn.py evaluation).
- Metrics HUD: trigger accuracy / obstacle avoidance success rate / direction error / GF latency, real-time + cumulative.
- Score correction: only count rounds that "constitute a collision threat" (collision time < threshold); false alarms counted separately.

## 4. Control Authority Toggle (minimal implementation, safety-related)

- Two-state toggle: 🛒 Manual (SNN only observes and records, never outputs) / 🤖 Biomimetic (SNN in full control).
- Any pilot input immediately takes over and overrides SNN output (zero latency).
- Fail-safe: any anomaly causes SNN output to zero = manual mode.
- Real-hardware three-mode arbitration (assist modes, etc.) listed as future work, not in v1.

## 5. Experiment Matrix (backbone of REPORT.md)

| Group | Input | Scenario | Metrics |
|---|---|---|---|
| A Control | Fusion / pure vision / pure wind | Clear weather | Trigger accuracy, success rate, direction error, latency |
| B Environment | Primarily fusion | Strong wind / pitch black | Same as above, quantify degradation |
| C Sneak attack speed | Fusion | Low / medium / high speed | Takeoff distance, success rate |
| D Cross-platform | Fusion | Clear weather | Fruit fly body vs drone body: success rate, time-to-position |

Each cell ≥5 repetitions (different seeds), report mean ± std dev.

## 6. Technical Notes

- Reuse: snn_runtime.js (inference), snn_trained.json (v3 weights: trigger 79.9%, success 90.3%, direction 10.7°, latency 7.65ms).
- Physics: custom lightweight integrator (sphere/rigid body level), units in cm and cm/ms, consistent with training formulas (looming = −2sṙ/(r²+s²)×1000; wind pressure u = s²|v|/r²).
- Pseudo-random fixed seed; evaluate.js outputs JSON for report reference.
- Acceptance follows A semantics (veto) / B numbers / C visuals / D scientific rigor — four checklists.

## 7. Risks

- 3D performance: grass blades and multi-entity instancing, target 60fps; if not met, reduce grass density first.
- Training data is synthetic cues (not measured), report must state this; drone application requires PX4 SITL → real hardware pipeline verification (future work).
