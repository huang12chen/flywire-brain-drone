**Conclusion: Maintain 50k training samples without reduction** (director approval: data quality over wall-clock time).

| Speed Test Item | Result | Notes |
|---|---|---|
| Training batch (B=64, forward+backward+step) **short burst** | 0.119 s/batch | `v4\speed_test.json`, extrapolated 50k ≈ **94 s/epoch** (optimistic) |

| B=1 evaluation forward | 6.0 ms/sample | All evaluations ≈ 1–2 min/seed |

**Root cause**: `v4\batch_probe.py` item-by-item comparison proves bottleneck is **OpenMP default spin-wait (KMP_BLOCKTIME=200ms)**:
`OMP_WAIT_POLICY=PASSIVE, KMP_BLOCKTIME=0` makes same batch computation **3–5× faster**. Both variables fixed at top of `train_snn_v4.py` (before import torch).
**Lesson**: Short burst speed tests cannot extrapolate to sustained loads; this machine is 12-core/16-thread shared environment, external tasks cause 2–3× fluctuation.
